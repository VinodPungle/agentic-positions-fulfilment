# Rollback plan: v1.4.0 -> v1.3.3

## When to use this
The `v1.4.0` deployment is misbehaving (elevated error rate, failed health checks,
broken functionality) and needs to be reverted to the last known-good release.

## 1. Revert the deployment
```
az containerapp update \
  -g globant-test-rg -n agentic-fulfilment-app \
  --image globantfulfilmentacr.azurecr.io/agentic-fulfilment-app:1.3.3
```
This points the Container App back at the exact image that was running before
`v1.4.0` was deployed — no rebuild needed, the image is already in the registry.

## 2. Database / config
No database-layer code changed in this release — reverting the container image
is sufficient, no index/schema reversal needed.

## 3. Verify the rollback succeeded
- `az containerapp revision list -g globant-test-rg -n agentic-fulfilment-app --query "[].{name:name,health:properties.healthState,traffic:properties.trafficWeight}" -o table`
  — confirm the new revision is `Healthy` and has 100% traffic.
- `curl https://<app-fqdn>/api/` — confirm a 200 response.
- Check Application Insights (`requests` and `exceptions` tables) for the 5-10 minutes
  after rollback — error rate should return to baseline, no new exception spike.
- If the original issue was reported by a user, confirm with them that it's resolved.

## 4. Follow-up
File an issue capturing what went wrong in `v1.4.0` before re-attempting the release.
